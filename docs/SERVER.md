# Свой маленький сервер для онлайн-комнат

Игра работает и без сервера: онлайн-комнаты используют бесплатный публичный посредник PeerJS. Свой сервер нужен, чтобы не зависеть от чужого сервиса и (по желанию) помочь игрокам из «трудных» сетей. **Игровые данные через него не идут**: он только сводит игроков по коду комнаты. Партия по-прежнему живёт в браузере хоста.

Что запускается (`deploy/docker-compose.yml`):

| Часть | Зачем | Обязательно |
|---|---|---|
| **peerjs** | посредник: игроки находят друг друга по коду комнаты | да |
| **caddy** | HTTPS и сертификат (без HTTPS страница на GitHub Pages не сможет подключиться) | да |
| **turn** (coturn) | запасной путь для сетей, где прямое соединение невозможно | нет |

Нагрузка крошечная: хватит самой маленькой машины (1 ядро, 512 МБ–1 ГБ памяти).

## 1. Где взять машину

Цены и условия бесплатных тарифов меняются, проверьте их на сайте перед оплатой.

- **Дешёвый VPS** (около 4–6 долларов в месяц у многих хостеров): проще всего, не нужны особые настройки.
- **Бесплатные квоты облаков** (например, виртуальная машина e2-micro в Google Cloud или Always Free у Oracle): бесплатно, но нужна банковская карта, а у Google бесплатная квота действует только в некоторых регионах.
- **Свой компьютер или Raspberry Pi дома**: бесплатно, но нужны проброс портов 80 и 443 на роутере и постоянный белый IP.

Нужна Linux-машина (подойдёт Ubuntu 22.04 или новее) с открытыми портами **80** и **443** (и **3478/udp** плюс **49152–49200/udp**, если нужен TURN).

## 2. Адрес

Нужно имя, которое указывает на ваш сервер:

- есть свой домен: создайте запись `A` вида `peer.ваш-домен.ru`, указывающую на IP машины;
- домена нет: подойдёт имя на основе IP через сервис sslip.io. Для IP `203.0.113.7` адрес будет `203-0-113-7.sslip.io`. Общие сервисы иногда упираются в лимиты выдачи сертификатов, тогда используйте свой домен или бесплатный поддомен (например, от DuckDNS).

## 3. Запуск

На машине:

```bash
# Docker (если ещё нет)
curl -fsSL https://get.docker.com | sh

git clone https://github.com/Ikonido/shelter-protocol.git
cd shelter-protocol/deploy
cp .env.example .env
nano .env            # впишите DOMAIN (и PUBLIC_IP, TURN_USER, TURN_PASS, если нужен TURN)

docker compose up -d                       # только посредник и HTTPS
# docker compose --profile turn up -d     # то же плюс TURN
```

Проверка (на любом компьютере с Node.js, из папки проекта):

```bash
node scripts/check-server.mjs peer.ваш-домен.ru
```

Скрипт напишет `OK` и подскажет, какие значения вписать дальше.

## 4. Подключить сайт к своему серверу

В репозитории на GitHub: **Settings → Secrets and variables → Actions → Variables** (вкладка Variables) добавьте:

| Имя | Значение |
|---|---|
| `VITE_PEER_HOST` | `peer.ваш-домен.ru` |
| `VITE_PEER_PORT` | `443` |
| `VITE_PEER_SECURE` | `true` |

Для TURN (по желанию): переменные `VITE_TURN_URL` = `turn:peer.ваш-домен.ru:3478`, `VITE_TURN_USER` = значение `TURN_USER`, а пароль положите во вкладку **Secrets** под именем `VITE_TURN_PASS`.

После этого перезапустите деплой (Actions → «Deploy to GitHub Pages» → Run workflow) или просто сделайте любое слияние в `main`. Пока переменные не заданы, игра использует публичный посредник, как раньше. Откатиться можно, удалив переменные и пересобрав сайт.

## Что важно знать

- **Пароль TURN виден в коде сайта.** Это свойство статического сайта: любой может открыть его и взять пароль. Поэтому в конфигурации стоят квоты (общий предел трафика и числа соединений) и запрещены частные адреса. Не используйте для TURN пароль, который вы где-то ещё применяете, и при подозрении на злоупотребление смените его и пересоберите сайт.
- **Хост всё ещё нужен.** Если хост закрыл вкладку, партия заканчивается. Свой сервер этого не меняет (для этого понадобилось бы переносить состояние партии на сервер).
- **Обновления.** Раз в пару месяцев: `cd shelter-protocol/deploy && docker compose pull && docker compose up -d`.
- **Безопасность машины.** Включите автоматические обновления системы и закройте всё, кроме нужных портов. Вход на машину лучше только по SSH-ключу.
