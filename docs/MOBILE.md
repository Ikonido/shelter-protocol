# Телефонное приложение: как раздавать дёшево

Приложение уже является **PWA** (манифест, иконки, service worker, офлайн). Это самый дешёвый и удобный путь — магазин не нужен.

| Путь | Стоимость | Что получает игрок | Комментарий |
|---|---|---|---|
| **1. PWA с GitHub Pages** (уже сделано) | 0 ₽ | Открыл ссылку/QR → «Установить» → иконка на экране, офлайн, обновляется само | Android и iOS. Раздел «Установить на телефон» в меню показывает QR на сайт и инструкции. |
| **2. Google Play (TWA)** | разово $25 | Обычное приложение из Play, внутри — ваш PWA | Оборачивается без изменения кода, см. ниже. |
| **3. APK для ручной установки** | 0 ₽ | Файл `.apk` из GitHub Releases | Тот же TWA-пакет, но без публикации в магазине; нужно разрешить установку из неизвестных источников. |
| **4. App Store (iOS)** | $99/год + Mac | Приложение из App Store | Не рекомендуется: нужна обёртка (Capacitor) и отдельная проверка Apple, «тонкие» обёртки над сайтом часто отклоняют. На iOS достаточно PWA. |

## 1. PWA (рекомендуется)
1. Включите GitHub Pages: *Settings → Pages → Source: GitHub Actions*. Workflow `.github/workflows/pages.yml` соберёт и опубликует сайт при пуше в `main`.
2. Адрес будет `https://<user>.github.io/shelter-protocol/` (https обязателен для установки и офлайна — Pages его даёт).
3. Раздайте QR из экрана «Установить на телефон» (или любой генератор QR на этот адрес).
   - **Android (Chrome):** кнопка «Установить приложение» в игре, либо меню ⋮ → «Установить приложение».
   - **iPhone/iPad (Safari):** «Поделиться» → «На экран “Домой”».
4. Обновления: service worker берёт свежую страницу при наличии сети; ничего переустанавливать не нужно.

Собственный домен (необязательно, ~несколько сотен ₽/год): добавьте его в настройках Pages — он пригодится для Play (п. 2).

## 2. Google Play через TWA (Trusted Web Activity)
Нужно: аккаунт разработчика Google Play (разово $25), публичный https-адрес сайта (п. 1).
```bash
npm i -g @bubblewrap/cli          # или используйте https://www.pwabuilder.com — то же без командной строки
bubblewrap init --manifest=https://<ваш-адрес>/manifest.webmanifest
bubblewrap build                  # создаст app-release-signed.apk / .aab и подскажет SHA-256 ключа
```
Затем:
1. Опубликуйте файл `/.well-known/assetlinks.json` с отпечатком ключа подписи (Digital Asset Links) — без него приложение откроется с адресной строкой. На GitHub Pages для проекта (`/shelter-protocol/`) файл должен лежать в корне домена, поэтому удобнее собственный домен или репозиторий `<user>.github.io`.
2. Загрузите `.aab` в Play Console, заполните карточку (скриншоты, описание, политика конфиденциальности — можно сослаться на `SECURITY.md`).
3. Актуальные требования Play к новым аккаунтам (например, закрытое тестирование перед публикацией) проверьте в Play Console — они меняются.

## 3. APK без магазина
Результат `bubblewrap build` (`app-release-signed.apk`) выложите во вкладке *Releases* репозитория. Игроки скачивают и устанавливают файл, разрешив установку из неизвестных источников. Ключ подписи храните отдельно и не коммитьте.

## Обновления на телефоне
Установленный PWA обновляется сам при запуске, но кеш браузера и service worker иногда держат старую версию. Для этого в приложении есть кнопка **«Проверить обновления»** (главный экран, внизу): она сравнивает версию с опубликованной и по кнопке «Обновить» сбрасывает кеши и перезагружает приложение без потери партий и паков.

## Ограничения
- PWA и офлайн требуют https (или localhost). В LAN-режиме страница идёт по `http://` — установка как приложения там недоступна, но игра работает.
- Я не проверял установку на реальных телефонах: в среде разработки проверены манифест (Chromium: нет ошибок установки), регистрация service worker и работа офлайн.
