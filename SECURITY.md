# Безопасность и конфиденциальность

Приложение полностью клиентское: нет аккаунтов, аналитики и сторонних запросов, кроме сетевой игры (см. ниже).

## Что защищено
| Угроза | Мера |
|---|---|
| Повреждённое сохранение партии | Сохранённая партия в `localStorage` проходит `validateSavedGame` (структура, типы, допустимые фазы); при несоответствии игра стартует с чистого листа, а не падает. |
| Вредоносный пак (файл / ссылка `#pack=` / localStorage) | Любые внешние данные проходят `sanitizePack`: типы, лимиты длины, whitelist полей; файлы ≤ 2 МБ, ссылки ≤ 20 000 символов (защита от «бомбы» распаковки lz-string). |
| XSS | Нет `dangerouslySetInnerHTML`/`eval`; React экранирует текст. Production-сборка отдаётся с CSP (`script-src 'self'`, `connect-src` только сам сайт и брокер), `referrer: no-referrer`. |
| Злонамеренный хост онлайн-игры | Клиент пересобирает присланное состояние (`sanitizeView`): проверка структуры, обрезка строк, ≤ 20 игроков, ≤ 200 записей журнала; некорректное состояние отбрасывается. |
| Злонамеренный гость | Хост проверяет каждое действие (фаза, жив ли игрок, допустимая цель, категория); один канал — один участник; лимит 30 сообщений/с (иначе отключение); рукопожатие за 10 с; ≤ 40 «висящих» соединений; блокировка комнаты и исключение игроков в лобби. |
| Утечка скрытых карт | Хост вырезает чужие закрытые карты и `seed` до отправки; при тайном голосовании чужие бюллетени не отправляются ни во время, ни после голосования. Покрыто тестами. |
| Подмена игрока | Переподключение по случайному 128-битному токену (`crypto.getRandomValues`), токен не рассылается другим; удаляется при выходе. |
| Чужие люди с кодом комнаты | Временный QR-«билет» (5 минут, ротация, мгновенный отзыв), режим «Вход только по QR», блокировка комнаты. Билет — случайные 30 бит: это замок от случайных гостей, а не криптографическая защита. |
| LAN-сервер открыт наружу | `scripts/lan-server.mjs` принимает только частные адреса (RFC1918, loopback, link-local) на уровне TCP; раздаёт только `dist/`. |
| Камера при сканировании QR | Видео обрабатывается только на устройстве (`getUserMedia` → кадры в canvas → распознавание в браузере) и никуда не отправляется и не сохраняется; поток останавливается при закрытии сканера. Доступ спрашивает сам браузер, работает только по `https` (в LAN по `http` браузер камеру блокирует, остаётся ввод кода). Содержимое QR проходит `parseInvite`: принимается только ссылка `#join=КОД[.БИЛЕТ]` или код комнаты, чужие QR игнорируются. |
| Уязвимые зависимости | `npm audit` в CI, Dependabot. |

## Что НЕ защищено (честные ограничения)
- **Хост всё видит.** Состояние игры авторитетно хранится в браузере хоста; технически подкованный хост может подсмотреть чужие карты. Играйте с тем, кому доверяете.
- **Одно устройство (Pass-and-Play / настольный режим).** Экран-«шторка» — защита от случайного подглядывания, не от владельца устройства: сохранённая партия лежит в localStorage открытым текстом.
- **Режим «Интернет».** Публичный брокер PeerJS и STUN-серверы (Google/Cloudflare) видят IP-адреса участников и код комнаты; содержимое игры идёт напрямую и шифруется (DTLS). Хотите приватности — используйте LAN или свой брокер (`VITE_PEER_HOST`) и свой STUN/TURN.
- **Режим LAN работает по `http://`.** Страницу и рукопожатие в локальной сети нельзя считать защищёнными от злоумышленника в той же сети (подмена скриптов возможна). Используйте доверенную сеть или личную точку доступа. Игровые данные между устройствами при этом шифруются WebRTC.
- **Код комнаты — 5 символов без пароля.** Перебор возможен; закрывайте комнату после сбора игроков, выгоняйте лишних; включайте «Вход только по QR».
- **Лимит ссылок:** распаковка lz-string не ограничивается по выходу, только по входу — «бомба» ≤ 20 000 символов всё ещё может ненадолго занять вкладку.
- Имена игроков не проверяются на «подделку» (можно назваться «Хост»).
- **CSP задана тегом `<meta>`.** GitHub Pages не позволяет менять HTTP-заголовки, поэтому директива `frame-ancestors` недоступна: страницу можно встроить во фрейм чужого сайта. Для этого нужен собственный сервер с заголовками (см. `docs/SERVER.md`).
- **Пароль TURN виден в коде сайта** (подробнее в `docs/SERVER.md`): им может воспользоваться любой посетитель. Используйте отдельную учётную запись с квотами и меняйте пароль при злоупотреблении.
- **Канал данных.** Сообщения больше 12 КБ режутся на части (`src/lib/chunk.ts`), потому что канал PeerJS в режиме json отвергает сообщения от 16 КБ. Принимающая сторона собирает не больше одного сообщения за раз и ограничивает число и размер частей; хост принимает только json-каналы.
